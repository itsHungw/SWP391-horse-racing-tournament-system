# Race Media (Highlights) Design

Date: 2026-06-30
Status: approved design direction (MVP: YouTube, one highlight per race)
Revision: 3 (further hardened after review -- see "Review hardening changelog")

## Goal

Let an organizer (or admin) attach a video highlight to a race after the official
result, and show it to spectators on the Race Detail page and the Championship Detail
page. For the MVP the only source is a YouTube link.

The feature is named "Race Highlight" for the product, but is built as a generic
"Race Media" layer so that YouTube can later be joined or replaced by uploaded video,
HLS, or a live stream without reworking the spectator UI or the public API contract.

The guiding principle is "design the seam, not the cathedral": the database schema and a
small provider interface are future-proof now; the UI ships YouTube-only and gains a
provider picker only when a second provider actually exists.

## Core Decisions

1. Product name = "Race highlight". Architecture/table = "Race Media" (provider-based).
2. MVP stores exactly one media row per race: `media_type = HIGHLIGHT`, `provider = YOUTUBE`.
3. The stored source of truth is a normalized `provider_video_id`, never the raw URL.
4. Accept the documented YouTube URL shapes -- `watch?v=`, `youtu.be/`, `embed/`,
   `shorts/`, `live/` -- via a URI parser with a host whitelist (not a mega-regex), and
   normalize to the 11-char video id. We do not promise "every" YouTube URL; the
   supported set is explicit and tested.
5. Status is `DRAFT | PUBLISHED` (mirrors `BlogStatus`). A draft can be saved at any
   time; Publish is locked until the race result is official AND the media is verified.
6. Publish gate = race `status in {RESULT_CONFIRMED, PUBLISHED}` (see `RaceStatus`) AND
   `verification_status = VERIFIED`.
7. Validation is split into two independent layers (review hardening, P1):
   - Structural (offline): parse + normalize the video id. If no id can be extracted the
     draft cannot be saved (`422 INVALID_YOUTUBE_URL`).
   - Embeddable (network, best-effort): a YouTube oEmbed call. This NEVER blocks saving a
     structurally-valid draft. If oEmbed is unreachable or rejects the video, the draft is
     still saved with `verification_status = FAILED` (or `UNVERIFIED`) and a warning; only
     Publish is blocked until verification succeeds.
8. oEmbed verification is best-effort, not a permanent guarantee (review hardening, P2). A
   video can be deleted or made private later. We record `last_verified_at` and
   `provider_error_code`; scheduled re-validation is future work, not MVP.
9. On successful verification the oEmbed `title` and `thumbnail_url` are snapshotted into
   the row. Spectator views never call YouTube per request.
10. The displayed title defaults to the oEmbed title; the organizer may override it with a
    custom title (optional field, e.g. a Vietnamese caption).
11. Authorization: the organizer who manages the race's tournament may add/edit
    (`Tournament.isManagedBy`); an admin may override / unpublish / remove any highlight.
12. Spectators only ever see media that is `PUBLISHED` and `VERIFIED`.
13. No provider-picker UI in the MVP. The `provider` column exists in the schema; the UI
    is YouTube-only.

## Data Model

New table `race_media` (migration `V20`). Postgres dialect, matching existing migrations.

| column                | type          | notes                                                        |
| --------------------- | ------------- | ------------------------------------------------------------ |
| `id`                  | bigint PK     | `generated by default as identity`                           |
| `race_id`             | bigint NOT NULL | FK `races(id)`                                             |
| `media_type`          | varchar(40) NOT NULL | default `'HIGHLIGHT'`; CHECK in ('HIGHLIGHT')          |
| `provider`            | varchar(40) NOT NULL | default `'YOUTUBE'`; CHECK in ('YOUTUBE')             |
| `provider_video_id`   | varchar(64) NOT NULL | normalized YouTube id                                 |
| `source_url`          | varchar(500) NOT NULL | original pasted URL, kept for audit/reference        |
| `title`               | varchar(300) NULL | organizer override; falls back to `provider_title`       |
| `provider_title`      | varchar(300) NULL | snapshot from oEmbed                                      |
| `thumbnail_url`       | varchar(500) NULL | snapshot from oEmbed                                      |
| `status`              | varchar(20) NOT NULL | default `'DRAFT'`; CHECK in ('DRAFT','PUBLISHED')      |
| `verification_status` | varchar(20) NOT NULL | default `'UNVERIFIED'`; CHECK in ('UNVERIFIED','VERIFIED','FAILED') |
| `last_verified_at`    | timestamp(6) NULL | last successful oEmbed verification                      |
| `provider_error_code` | varchar(40) NULL | last provider failure reason (e.g. `NOT_EMBEDDABLE`, `TIMEOUT`) |
| `published_at`        | timestamp(6) NULL |                                                          |
| `published_by`        | bigint NULL   | FK `users(id)`                                               |
| `created_by`          | bigint NOT NULL | FK `users(id)`                                             |
| `updated_by`          | bigint NULL   | FK `users(id)`                                             |
| `created_at`          | timestamp(6) NOT NULL |                                                       |
| `updated_at`          | timestamp(6) NULL |                                                          |
| `deleted_at`          | timestamp(6) NULL | soft delete (mirrors `Race`)                             |

Constraints / indexes (review hardening, P2):

- One live media per race+type (the MVP invariant), enforced at the DB level like wallet
  idempotency, but keyed by `(race_id, media_type)` so the generic layer can later hold a
  HIGHLIGHT and a RECAP for the same race:
  `CREATE UNIQUE INDEX UQ_race_media_one_per_race_type ON race_media(race_id, media_type) WHERE deleted_at IS NULL;`
  (Postgres partial unique index.) The same invariant is ALSO enforced in the service layer
  so it is testable on H2 (see Test Plan).
- Read index: `CREATE INDEX IX_race_media_race_status ON race_media(race_id, status);`
- CHECK constraints on `status`, `provider`, `media_type`, `verification_status`.
- Multi-column invariant (review hardening, P2):
  `CHECK (status <> 'PUBLISHED' OR verification_status = 'VERIFIED')` -- a row can never be
  PUBLISHED without being VERIFIED. Enforced in the service too.
- FKs on `race_id`, `created_by`, `updated_by`, `published_by`.

Deliberately not added now (YAGNI -- add when a second provider lands):
`playback_url`, `duration_seconds`, uploaded-asset references, provider credentials.

## Provider Abstraction (the seam)

```java
interface HighlightProvider {
    MediaProviderType type();                 // YOUTUBE
    String normalizeId(String url);           // structural; throws InvalidMediaUrlException
    ProviderMeta verify(String videoId);      // network best-effort; throws VideoNotEmbeddableException / ProviderUnavailableException
    String embedUrl(String videoId);          // youtube-nocookie embed URL, rebuilt from id
}
record ProviderMeta(String title, String thumbnailUrl) {}
```

- Only implementation now: `YouTubeProvider`.
- `normalizeId` parses with `java.net.URI` and a host whitelist
  (`youtube.com`, `www.youtube.com`, `m.youtube.com`, `youtu.be`), reads the id from the
  known path/query shapes (`watch?v=`, path `/embed/{id}`, `/shorts/{id}`, `/live/{id}`,
  or `youtu.be/{id}`), and validates the id against `[A-Za-z0-9_-]{11}`. No regex URL
  parsing -- this avoids `evil.com/youtube.com/...` style bypasses (review hardening, P2).
- `verify` calls `https://www.youtube.com/oembed?url=<videoUrl>&format=json` with short
  connect/read timeouts via Spring `RestClient`. A 401/404 or any non-2xx means the video
  is missing, private, or has embedding disabled -> `VideoNotEmbeddableException`; a
  timeout/IO error -> `ProviderUnavailableException`. Neither aborts a draft save.
- `embedUrl` is always rebuilt from `provider_video_id`; the stored `source_url` is never
  used as an iframe src.
- `RaceMediaService` selects the provider by the row's `provider` field (always YOUTUBE now).

## Backend Endpoints

Organizer -- `hasRole('ORGANIZER')`, ownership checked via `Tournament.isManagedBy`, added
to `OrganizerRaceController` (prefix `/api/v1/organizer/races`):

| method | path                          | purpose                                                              |
| ------ | ----------------------------- | ------------------------------------------------------------------- |
| GET    | `/{raceId}/media`             | current media (draft or published), or empty                        |
| POST   | `/{raceId}/media/validate`    | body `{url}` -> normalize + best-effort oEmbed, return `{videoId,title,thumbnailUrl,verificationStatus,providerErrorCode}`; no persistence (powers preview) |
| PUT    | `/{raceId}/media`             | body `{url, title?}` -> upsert draft. Structural failure = 422; oEmbed failure = saved as FAILED + warning (200) |
| POST   | `/{raceId}/media/publish`     | re-verify oEmbed + assert race status official -> set `PUBLISHED`, `published_at/by`. Blocked if not verified |
| POST   | `/{raceId}/media/unpublish`   | back to `DRAFT`                                                      |
| POST   | `/{raceId}/media/reverify`    | re-run oEmbed on a saved draft (recover from a transient FAILED)     |
| DELETE | `/{raceId}/media`             | soft delete                                                         |

Edit and republish semantics (review hardening, P1): `PUT` compares the incoming
normalized video id against the stored one.
- If the video id changes, the row is treated as new content: `status -> DRAFT`,
  `verification_status -> UNVERIFIED`, `published_at`/`published_by` cleared, and a fresh
  best-effort verify runs. Spectators stop seeing it immediately (public read requires
  `PUBLISHED + VERIFIED`) until it is republished.
- If only the title changes on a `PUBLISHED + VERIFIED` row, it updates in place and stays
  published -- the video identity is unchanged, so no re-verify or republish is required.
- Publishing again after a demote sets a fresh `published_at`.

Admin override -- `hasRole('ADMIN')`, no ownership restriction, records the moderating
actor (new `AdminRaceMediaController`, prefix `/api/v1/admin/races`): same op set.

Public read (review hardening, P1 -- do NOT bloat the shared `RaceResponse`):

- `RaceResponse` is a flat shared DTO mapped by a common mapper; adding a per-race media
  lookup there would risk N+1 and could leak drafts. Instead:
  - Race detail: a dedicated read returns a `RaceMediaPublicResponse | null` filtered in
    the query to `status = PUBLISHED AND verification_status = VERIFIED`.
  - Championship detail: batch-fetch with
    `RaceMediaRepository.findPublishedByRaceIds(Collection<Long> raceIds)` -> one query,
    no N+1, mapped to `[{ raceId, raceName, videoId, embedUrl, title, thumbnailUrl }]`.
- Optional lazy endpoint `GET /api/v1/races/{raceId}/highlight` for facade-on-demand loads.

DTOs:
- `RaceMediaRequest(url, title?)`
- `RaceMediaValidateResponse(videoId, title, thumbnailUrl, verificationStatus, providerErrorCode, message)` -- a status, not a bare boolean, so the FE can tell FAILED (rejected) apart from UNVERIFIED (timeout/unreachable).
- `RaceMediaResponse(id, provider, videoId, embedUrl, title, thumbnailUrl, status, verificationStatus, lastVerifiedAt, publishedAt, canPublish, publishBlockedReason)` -- `canPublish` + reason let the FE render the locked state without re-deriving rules.
- `RaceMediaPublicResponse(videoId, embedUrl, title, thumbnailUrl)` -- published+verified only.

## Validation / Error Contract

| condition                                       | http | code                    | message                                                            |
| ----------------------------------------------- | ---- | ----------------------- | ------------------------------------------------------------------ |
| URL has no extractable video id (save)          | 422  | `INVALID_YOUTUBE_URL`   | "That doesn't look like a YouTube link."                           |
| oEmbed rejects video (save)                      | 200  | warning `VIDEO_NOT_EMBEDDABLE` | saved as FAILED; "Saved, but YouTube says this video can't be embedded. Re-check it before publishing." |
| oEmbed unreachable/timeout (save)               | 200  | warning `PROVIDER_UNAVAILABLE` | saved as UNVERIFIED; "Saved. Couldn't reach YouTube to verify -- try Re-verify before publishing." |
| Publish while not verified                      | 422  | `MEDIA_NOT_VERIFIED`    | "Verify the video before publishing."                              |
| Publish while race result not official          | 409  | `RESULT_NOT_OFFICIAL`   | "Publish unlocks once the result is confirmed."                    |
| Publish reverify rejects the video              | 422  | `VIDEO_NOT_EMBEDDABLE`  | sets `verification_status=FAILED`, stays DRAFT; "YouTube says this video can't be embedded." |
| Publish reverify times out / unreachable        | 503  | `PROVIDER_UNAVAILABLE`  | state unchanged (stays DRAFT); "Couldn't reach YouTube to verify. Try again."               |

Key change from revision 1: a flaky provider never costs the organizer their draft. Saving
is gated only by structural validity; embeddability gates Publish. Publish performs a fresh
reverify and never flips to PUBLISHED on a provider failure (the two rows above).

## Security (review hardening, P1)

- Ownership: organizer ops go through `Tournament.isManagedBy`; admin ops bypass it but
  record the actor in `published_by` / audit.
- The iframe `src` is always rebuilt from `provider_video_id`, never from the stored
  `source_url` -- this prevents `javascript:` or arbitrary-embed injection through a crafted
  URL. `source_url` is retained only for audit display.
- The oEmbed call targets a fixed host (`www.youtube.com`), uses short timeouts, and does
  not follow arbitrary redirects.
- CSP and iframe layering -- the CSP that gates iframe rendering belongs to the document
  that hosts the iframe (the frontend SPA), not this API's response CSP. The current API
  CSP at `AppSecurityProperties` is `default-src 'self'; frame-ancestors 'none'; ...`
  (no `frame-src`), which only matters if the backend ever serves the SPA.
  - Frontend CSP must allow: `frame-src https://www.youtube-nocookie.com;`
    `img-src 'self' https://i.ytimg.com data:;`
  - Iframe element attributes: `allow="accelerometer; autoplay; clipboard-write;`
    `encrypted-media; gyroscope; picture-in-picture; web-share"`, `allowfullscreen`,
    `referrerpolicy="strict-origin-when-cross-origin"`, optional `sandbox`
    (`allow-scripts allow-same-origin allow-presentation`).
  - `frame-ancestors 'none'` / `frameOptions deny` on our own pages stay as-is; they
    protect us from being framed and are unrelated to us framing YouTube.

## Frontend

Organizer / Admin (office theme -- parchment / charcoal / brass):
- A "Media" tab inside Race Control, alongside Overview / Field / Results.
- States: Empty / Draft (publish locked, amber lock banner) / Published / Admin override --
  per the approved mockup. Locked Publish shows why (`publishBlockedReason`). A FAILED/
  UNVERIFIED draft shows a "Re-verify" affordance instead of losing the user's link.
- Validate -> preview card with the oEmbed title, thumbnail, and a "Verified - embeddable"
  line before Publish is offered.
- Components: `RaceMediaPanel`, `YouTubePreviewCard`, `useRaceMedia` hook, `raceMediaApi.ts`.
- Reuse office primitives (`StatusPill` for Draft/Published, `EmptyState`).

Public (cinematic theme -- "Night at the Races", gold/ivory):
- `RaceHighlightPlayer` on Race Detail -- gold-accent facade (thumbnail + play) that
  injects the iframe only on click.
- `ChampionshipHighlightsRail` on Championship Detail -- a list/grid of race highlights;
  races without a published highlight render a muted "no highlight yet" slot.
- A "Highlight" badge on race cards that have a published highlight.

## Embed & Performance

- Embed host is `youtube-nocookie.com/embed/{id}` (privacy-enhanced).
- Facade pattern everywhere: render the snapshot thumbnail + a play button; only mount the
  YouTube iframe on click. The Championship page can list many highlights without loading
  N iframes, and the public read is a single batch query (no N+1).

## Out of Scope (MVP) / Future

- Multiple clips, playlists, chapter markers (schema already allows multiple media_types).
- Uploaded video / HLS / live stream (provider expansion -- the reason for the generic schema).
- Scheduled re-validation / auto-unpublish on link rot (we store `last_verified_at` and
  `provider_error_code` now so this is a pure additive job later).
- Moderation queue, viewer reporting.
- Localization of the provider title (custom title field already covers the manual case).

## Migration Sketch (V20)

```sql
-- V20: Race Media -- one YouTube highlight per race (generic provider layer for future upload/live).
CREATE TABLE race_media (
    id bigint generated by default as identity not null,
    race_id BIGINT NOT NULL,
    media_type VARCHAR(40) NOT NULL DEFAULT 'HIGHLIGHT',
    provider VARCHAR(40) NOT NULL DEFAULT 'YOUTUBE',
    provider_video_id VARCHAR(64) NOT NULL,
    source_url VARCHAR(500) NOT NULL,
    title VARCHAR(300),
    provider_title VARCHAR(300),
    thumbnail_url VARCHAR(500),
    status VARCHAR(20) NOT NULL DEFAULT 'DRAFT',
    verification_status VARCHAR(20) NOT NULL DEFAULT 'UNVERIFIED',
    last_verified_at timestamp(6),
    provider_error_code VARCHAR(40),
    published_at timestamp(6),
    published_by BIGINT,
    created_by BIGINT NOT NULL,
    updated_by BIGINT,
    created_at timestamp(6) NOT NULL,
    updated_at timestamp(6),
    deleted_at timestamp(6),
    PRIMARY KEY (id),
    CONSTRAINT CK_race_media_status CHECK (status IN ('DRAFT','PUBLISHED')),
    CONSTRAINT CK_race_media_verification CHECK (verification_status IN ('UNVERIFIED','VERIFIED','FAILED')),
    CONSTRAINT CK_race_media_provider CHECK (provider IN ('YOUTUBE')),
    CONSTRAINT CK_race_media_type CHECK (media_type IN ('HIGHLIGHT')),
    CONSTRAINT CK_race_media_published_verified CHECK (status <> 'PUBLISHED' OR verification_status = 'VERIFIED')
);
ALTER TABLE race_media ADD CONSTRAINT FK_race_media_race FOREIGN KEY (race_id) REFERENCES races(id);
ALTER TABLE race_media ADD CONSTRAINT FK_race_media_created_by FOREIGN KEY (created_by) REFERENCES users(id);
ALTER TABLE race_media ADD CONSTRAINT FK_race_media_updated_by FOREIGN KEY (updated_by) REFERENCES users(id);
ALTER TABLE race_media ADD CONSTRAINT FK_race_media_published_by FOREIGN KEY (published_by) REFERENCES users(id);
CREATE UNIQUE INDEX UQ_race_media_one_per_race_type ON race_media(race_id, media_type) WHERE deleted_at IS NULL;
CREATE INDEX IX_race_media_race_status ON race_media(race_id, status);
```

Note: tests run on H2 with `ddl-auto` create-drop, where Postgres partial indexes and some
CHECK syntax are not exercised. The one-per-race-type invariant is therefore enforced in
the service layer as the primary guard (testable on H2), with the DB index as defense in
depth (see Test Plan).

## Test Plan

- `normalizeId`: all supported URL shapes (`watch`, `youtu.be`, `embed`, `shorts`, `live`,
  `m.youtube.com`), plus rejected cases (wrong host, `evil.com/youtube.com/...`, bad id length).
- `YouTubeProvider.verify` mocked: ok / not-embeddable / timeout -- assert the save-vs-publish
  split (timeout still saves draft as UNVERIFIED; publish blocked until VERIFIED).
- Publish gate: blocked when race not `RESULT_CONFIRMED`/`PUBLISHED`, blocked when not
  VERIFIED, allowed when both hold.
- Ownership: non-owner organizer -> 403; admin override -> 200.
- One-per-race-type: rejected by the service guard (primary, testable on H2).
- Public read returns only `PUBLISHED + VERIFIED` media; drafts and FAILED rows are invisible,
  and championship batch read issues a single query (no N+1).
- Because H2 tests build their schema from JPA `ddl-auto` and do NOT run Flyway, the migration
  CHECK constraints, the partial unique index, and the `published => verified` invariant are
  never exercised on H2. A dedicated `postgres-integration` profile (Testcontainers) runs the
  real migration and asserts these DB invariants; it is required before merge/deploy but kept
  out of the default fast suite so day-to-day CI stays Docker-free (review hardening, P2).

## Review hardening changelog

Revision 2 (incorporated from design review):
- P1 Provider off the critical write path -> `verification_status` + save/publish split.
- P1 Public DTO -> dedicated public projection + `findPublishedByRaceIds` batch, no
  `RaceResponse` bloat / draft leak.
- P1 CSP/iframe -> explicit frontend CSP `frame-src`/`img-src` + iframe attributes, with
  the frontend-vs-backend layering clarified.
- P2 oEmbed is best-effort -> wording fix + `last_verified_at` + `provider_error_code` +
  future scheduled re-validation.
- P2 Migration hardening -> CHECK constraints, `updated_by` FK, `(race_id, media_type)` unique.
- P2 URL parsing -> `java.net.URI` + host whitelist instead of a mega-regex; "all formats"
  claim dropped for an explicit supported set.
- P3 Encoding -> document rewritten ASCII-only to avoid mojibake.

Revision 3 (second review pass):
- P1 Edit-when-published -> explicit edit/republish semantics (video-id change demotes to
  DRAFT + re-verify; title-only edits in place and stays published).
- P1 Publish reverify failure -> `VIDEO_NOT_EMBEDDABLE` / `PROVIDER_UNAVAILABLE` error rows;
  state never flips to PUBLISHED on a provider failure.
- P2 `published => verified` -> multi-column DB CHECK plus service enforcement.
- P2 Validate response -> `verificationStatus` + `providerErrorCode` + `message` instead of a
  bare boolean.
- P2 Testcontainers -> a required `postgres-integration` profile (pre-merge/deploy), since H2
  builds schema from `ddl-auto` and never exercises the Flyway DB constraints.
