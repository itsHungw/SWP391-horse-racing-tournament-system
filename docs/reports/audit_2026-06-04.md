## 🔴 Critical Issues (Phải sửa ngay)

### 1. Lưu trữ Access Token trong LocalStorage (Lỗ hổng XSS)
- **File**: `frontend/src/utils/authSession.ts`, `frontend/src/pages/auth/AuthPage.tsx`
- **Nguy hiểm**: Hiện tại Access Token (chìa khóa đăng nhập) đang được lưu trần trụi trong `localStorage`. Nếu trang web bị dính lỗi XSS (hacker chèn được script độc hại vào bình luận hoặc form input), hacker có thể dùng lệnh `localStorage.getItem('accessToken')` để trộm chìa khóa này và mạo danh người dùng, chiếm toàn quyền tài khoản.
- **Cách sửa**: 
  - Cách 1: Lưu Access Token trong bộ nhớ RAM (React Context/Zustand) và chỉ dùng HttpOnly Cookie cho Refresh Token.
  - Cách 2: Chuyển hoàn toàn Backend sang trả về Access Token bằng HttpOnly Cookies để frontend không bị đụng vào token.

## 🟡 Warnings (Nên sửa)

### 1. Bật Show-SQL có thể gây nghẽn log
- **File**: `backend/src/main/resources/application.yml`
- **Vấn đề**: Đang cấu hình `jpa.show-sql: true` và `format_sql: true`.
- **Nguy hiểm**: Cứ mỗi thao tác liên quan database là backend lại in câu SQL ra log. Ở môi trường Dev thì tốt, nhưng nếu bưng nguyên file này lên Production, file log sẽ phình to chóng mặt gây hết ổ cứng, đồng thời việc in log sẽ làm tốc độ app bị chậm đi rất nhiều.
- **Cách sửa**: Tạo file `application-dev.yml` để bật, còn file `application.yml` chính thì đổi thành `false`.

### 2. Thiết lập Refresh Cookie chưa an toàn (Secure = false)
- **File**: `backend/src/main/resources/application.yml`
- **Vấn đề**: Đang thiết lập `app.auth.refresh-cookie-secure: false`.
- **Nguy hiểm**: Token duy trì đăng nhập (Refresh Token) có thể bị trình duyệt gửi qua đường truyền không an toàn (HTTP thường thay vì HTTPS). Nếu người dùng dùng Wifi công cộng, hacker có thể nghe lén và cắp Refresh Token này.
- **Cách sửa**: Khi deploy thực tế bắt buộc phải có HTTPS, nên cần set thông số này thành `true` ở môi trường Production.

## 🟢 Suggestions (Tùy chọn)

### 1. Thiếu cơ chế Rate Limiting (Chống Spam)
- Backend hiện tại chưa có cơ chế chặn gọi API liên tục (như Bucket4j hoặc rate limit filter).
- Hacker có thể chạy tool tự động gõ pass sai hàng ngàn lần ở API login, hoặc gọi API quên mật khẩu liên tục làm hệ thống quá tải và cạn tài nguyên gửi mail.
- **Gợi ý**: Thêm Rate Limiting đặc biệt cho nhóm API `/api/v1/auth/**`.

### 2. Nên dùng Lazy Loading cho Frontend
- File `AppRouter.tsx` khả năng cao đang load cứng toàn bộ các trang (kể cả trang Admin).
- **Gợi ý**: Dùng `React.lazy()` để tách nhỏ file. Khách vào trang nào thì tải code trang đó, app sẽ mượt và nhẹ hơn nhiều từ lúc mới khởi động.
