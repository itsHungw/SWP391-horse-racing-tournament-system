## Phiên 1 — Chuẩn hóa cấu trúc thư mục auth và user

**Thời gian:** 20:00 — 20:20  
**Công cụ AI:** Codex

### Câu hỏi của tôi

> Xem lại cấu trúc folder của auth chuẩn chưa, nếu chuẩn thì áp dụng cho các module còn lại.

### Câu trả lời của AI

AI đã kiểm tra cấu trúc backend hiện tại và xác nhận module `auth` nên giữ theo hướng feature-based:

1. `controller/` cho REST endpoints.
2. `dto/request/` và `dto/response/` cho dữ liệu API.
3. `entity/` cho JPA entities.
4. `repository/` cho Spring Data repositories.
5. `service/` cho business logic.
6. `email/` cho email sender abstraction.

AI cũng đề xuất không cần thêm tầng `service.impl` lúc này vì project còn nhỏ và service hiện tại chưa phức tạp.

### Tôi đã làm gì với câu trả lời đó

- Đổi convention `user/model` sang `user/entity`.
- Cập nhật các import từ `user.model.*` sang `user.entity.*`.
- Xóa package auth email cũ bị trùng.
- Giữ `EmailSender` và `LoggingEmailSender` trong `auth/email`.
- Chạy backend test để xác nhận refactor không làm hỏng JPA/Spring context.

## Phiên 3 — Chốt luồng register, profile và age verification

**Thời gian:** 22:50 — 23:05  
**Công cụ AI:** Codex

### Câu hỏi của tôi

> User chỉ register email, pass, confirm pass ở frontend, phone optional, verify, user có role spectator. Khi prediction thì xác minh giới tính, DOB modal popup, rồi khi user muốn ứng role khác thì điền full profile required. Bạn xem có ok không?

### Câu trả lời của AI

AI xác nhận flow hợp lý vì không bắt người dùng nhập full profile ngay từ đầu. Flow được chỉnh lại như sau:

1. Guest đăng ký tài khoản cơ bản.
2. User verify email.
3. Hệ thống gán role mặc định `SPECTATOR`.
4. Khi user muốn submit prediction thì kiểm tra age verification.
5. Nếu chưa xác minh tuổi, frontend hiển thị modal nhập `dateOfBirth` và `gender`.
6. Khi user muốn xin role khác như `HORSE_OWNER`, `JOCKEY`, `REFEREE` thì mới bắt complete full profile.

AI cũng nhắc rằng project đang dùng mô hình clean prediction game, không phải betting thật, nên cần tránh terminology như betting/wallet/place bet trong docs và code.

### Tôi đã làm gì với câu trả lời đó

- Chốt vẫn sẽ verify age cho prediction.
- Chốt tuổi tối thiểu cho prediction là 18.
- Chốt register vẫn giữ `fullName`.
- Chốt frontend register form gồm:
  - `fullName`
  - `email`
  - `password`
  - `confirmPassword`
  - `phone` optional
- Chốt backend register request không cần nhận `confirmPassword`; frontend tự validate để giữ service gọn.

## Phiên 4 — Cập nhật RegisterRequest theo flow mới

**Thời gian:** 23:05 — 23:15  
**Công cụ AI:** Codex

### Câu hỏi của tôi

> 18 tuổi, làm xong phần register + email verify, tôi sẽ tự commit.

### Câu trả lời của AI

AI đã cập nhật phần register/email verify theo flow đã chốt:

1. `RegisterRequest` nhận thêm `phone`.
2. `confirmPassword` chỉ dùng ở frontend, không đưa vào backend DTO.
3. `phone` là optional, nếu có thì lưu vào user.
4. User mới có các cờ mặc định:
   - `phoneVerified = false`
   - `ageVerified = false`
   - `profileCompleted = false`
5. User vẫn được tạo với:
   - `status = PENDING_EMAIL_VERIFY`
   - `emailVerified = false`
   - role mặc định `SPECTATOR`
6. Email verification vẫn tạo token, hash token và gửi qua `EmailSender`.

### Tôi đã làm gì với câu trả lời đó

- Cập nhật `RegisterRequest.java`.
- Cập nhật `AuthService.java` để normalize email và phone.
- Cập nhật `User.java` thêm các field verification/profile mới.
- Cập nhật SQL schema trong `database/001_create_tables.sql`.
- Cập nhật migration `database/003_auth.sql`.
- Mở rộng `AuthRegistrationIntegrationTest` với test:
  - register tạo user pending với role spectator.
  - register lưu phone optional.
  - register normalize email và gửi verification email.
  - verify email active user.
  - resend verification email tạo token mới.
